# 需求规格与当前验收（2026-10-10）

> 来源：《城迹入戏 Web MVP 产品功能与技术设计方案》第 1、6、17 节。
> 凡未提供真实来源的数据一律标注【待补充】，不得以占位内容冒充真实资料。

## 1. 产品定位

《城迹入戏》不是单纯的 AI 聊天页面，也不是传统景点导览网站，而是将**地方文化知识、空间路线、角色叙事、任务解谜和学习评价**连接起来的沉浸式文化剧本游平台。

用户闭环：选择主题 → 选择角色 → 进入路线 → 到达点位 → 与 AI NPC 对话 → 完成任务 → 解锁图鉴 → 形成结局 → 生成学习报告。

## 2. MVP 必须实现

- [x] 匿名 Session 与数据库进度保存（刷新恢复、跨Session隔离、清除已有测试）
- [x] 一个演示文化主题和一条路线
- [x] 5 个文化点位（实地点位坐标/定位未现场验收）
- [ ] 3 个玩家角色与3个NPC已实现；角色仅初始线索和称呼差异，初始任务/角色结局分支未完整实现
- [x] 6 个任务节点及后端答案、线索、奖励校验；没有独立图片识别任务
- [x] 3 个规则结局（完整探索hang/keep分支和末任务未完成结局）
- [ ] 虚拟/浏览器定位双模式已实现；实地精度、停留时间和现场体验仍待验证
- [ ] RAG机制与引用过滤已测试；正式文化授权/人审和真实模型质量未验收
- [x] 服务端剧情状态机、事务CAS、幂等奖励、线索、道具和图鉴
- [x] 数据库旅程报告与简版管理后台（任意剧情/点位编辑器不在当前实现中）
- [ ] Docker/PG/pgvector配置与部署文档已有；实际容器验收依赖可用运行环境

本表区分局部功能与完整需求。测试证据和未完成项以[最终审计](final-audit.md)、[测试记录](test-results.md)为准。14演示文化资料仍pending，没有为了勾选本表伪造正式知识审核。

## 3. 首版非目标

多城市 / 多租户 / 商业化会员；复杂拖拽剧情编辑器；AR、语音和小程序；实时多人游戏和支付；大模型微调；自动生成未经审核的文化史实。
