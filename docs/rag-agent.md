# RAG 与 NPC Agent（V0.1 骨架）

> 来源：技术方案第 13 节。

## 1. 文化知识入库流程

```
文化资料 → 来源与授权检查 → 清洗去重 → 语义切分 → 添加人物/年代/地点等元数据
        → 人工审核 → 向量化 → 建立索引 → 检索测试 → 发布
```

**未经审核（review_status != reviewed）的内容不得进入生产索引。**

## 2. 检索与生成流程（12 步）

1. 用户输入安全检测；
2. 识别意图并提取人物、地点、时期等实体；
3. 读取玩家角色、NPC 角色卡和当前剧情状态；
4. 按 NPC 知识边界与剧情披露范围过滤知识；
5. 执行关键词检索与向量检索；
6. 合并、去重和重排序；
7. 判断证据是否充分；
8. 组装角色、剧情、证据和 JSON 约束提示词；
9. 调用 DeepSeek / 通义千问 / Ollama 适配器；
10. 验证 JSON 结构、证据、角色一致性和安全性；
11. 校验模型建议动作；
12. 更新合法状态并返回界面。

## 3. 证据不足处理

触发条件：未检索到审核资料、检索分数低于阈值【待补充】、来源冲突、问题超出 NPC 知识边界、模型引用不存在的证据。

统一兜底回答：

> 现有资料无法确认这一内容。你可以继续探索相关点位，或查看已经审核的文化图鉴。

## 4. 内容类型约束

见 [database-schema.md](database-schema.md) 第 3 节：fact / disputed / legend / fiction，输出时必须明确标注。

## 5. LLM 适配器

- 提供方：`deepseek` / `qwen` / `ollama` / `mock`（本地开发与测试默认 mock）。
- 适配器位于 `backend/app/ai/llm/`，统一接口，业务代码不感知具体厂商。
- Embedding 模型与向量库选型：【待补充】（优先级 B）。
